# gdg_hackathon

## MVP implementation plan

This project is a lightweight web app for students who want to beat procrastination and prepare for exams under time pressure. The core idea is simple: help the user make progress over perfection.

### Product goal
A student should be able to:
- see a calm, motivating landing screen
- upload study materials
- enter a deadline or available study window
- receive a short, realistic study plan generated by Gemma 4
- leave with one small action they can start immediately

### MVP scope
The MVP should focus on one polished, demo-ready happy path:
1. User lands on a page with a predefined prompt and upload box.
2. User uploads study materials (text, PDF, or docs).
3. User enters a deadline and estimated daily study time.
4. The app sends the input to Gemma 4.
5. Gemma returns a study plan that is short, practical, and focused on progress.
6. The UI displays the plan clearly and encourages the user to begin now.

### Core user flow
- Landing screen
  - headline: “Beat procrastination. Start with one small study block.”
  - short description
  - predefined prompt example
  - upload box
  - deadline input
- result cards for the generated plan
- progress-oriented footer message

### Gemini API usage
The live Gemini integration lives in [app.py](app.py). It reads `GEMINI_API_KEY` from `.env`, uses `gemma-4-26b-a4b-it`, and includes a `thinking_config` plus a system instruction for the study-plan response. The chat flow is also implemented there in the `/api/chat` endpoint.

### Optional Gemini capabilities
The Step 7 items in the guide are optional SDK features. This app does not wire image upload, function calling, or search grounding into the product flow yet.

### Demo scenario
Use one concrete example for the demo:
- student uploads lecture notes
- enters a deadline of 3 days away
- states they can study 45 minutes per day
- the app returns a plan with:
  - 3 short sessions
  - one priority topic
  - one minimum-win task for today

### Implementation plan
#### Phase 1: core skeleton
- set up frontend and backend
- create landing page and form UI
- connect file upload input
- create dummy result view for testing

#### Phase 2: AI integration
- create backend endpoint for plan generation
- connect Gemma 4
- parse AI output into a clean result view
- add error handling and fallback response if the API fails

#### Phase 3: polish for demo
- add nice typography, spacing, colors, and micro-interactions
- improve copy to feel motivating rather than clinical
- add a loading spinner and success state
- prepare a short demo script

### What not to build in the MVP
To keep the scope realistic, avoid:
- user accounts
- saved history
- reminders or notifications
- chat-based tutoring
- many complex features beyond the one happy path

### Success criteria for the MVP
The MVP is successful if:
- the full flow works end to end once
- the plan generation feels useful and realistic
- the UI looks attractive and demo-ready
- the experience reinforces progress over perfection

### Suggested hackathon timeline
- Hour 1–2: scaffold app and create UI shell
- Hour 3–5: wire upload form and backend endpoint
- Hour 6–8: connect Gemma 4 and shape the output
- Hour 9–10: polish UI and rehearse demo

## Detailed implementation plan and current status

A working MVP starter has now been created for this repository.

### What has been implemented
- a polished landing page with a short wizard-style form
- an upload area for study materials
- a prompt field, deadline field, and study-time input
- a backend endpoint that accepts uploaded files and returns a study plan
- support for PowerPoint files from the study_material folder, plus .txt and .docx uploads
- a simple timeline-based plan view designed for demo use

### Code structure
- app.py: FastAPI backend, file parsing, and plan generation
- templates/index.html: UI shell and form
- static/styles.css: visual styling with the provided colour palette
- static/app.js: form submission and result rendering

### Demo flow
1. Open the app in the browser.
2. Upload one of the PowerPoint files from the study_material folder.
3. Enter a deadline and study time.
4. Press Generate plan.
5. Review the short plan, timeline, minimum win, and motivation note.

### Limitations and exceptions
- PDF parsing is not included in this starter version; the current demo path is optimized for .pptx, .docx, and .txt.
- The Step 7 Gemini SDK features are documented in the guide but are not part of the current app flow.
- This is a demo-focused MVP, not a production-grade study assistant.

### How to run locally
1. Install dependencies:
   - pip install -r requirements.txt
2. Start the app:
   - uvicorn app:app --reload
3. Open http://127.0.0.1:8000/

### Verified status
The app was tested locally with the real PowerPoint demo file from the study_material folder and returned a plan successfully.
